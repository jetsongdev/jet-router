Export function mergePatches(base, left, right). base is an array of strings. left and right are arrays of patch objects {start, end, lines}. start and end are integers with 0 <= start <= end <= base.length; lines is an array of strings. A patch replaces base[start:end] with lines; start=end is an insertion at that boundary. Within each side, patches must be given in ascending start order and must not conflict under the conflict rule below, including two insertions at the same boundary. Reject invalid input or a within-side conflict with RangeError. Ignore extra object properties. Never mutate or reuse base, patch arrays, patch objects, or lines arrays in the result.

Two patches conflict exactly when: both are insertions at the same boundary; or one is an insertion at p and the other is a nonempty range [s,e) with s <= p < e; or both are nonempty ranges with max(start) < min(end). A range ending at an insertion boundary does not conflict with that insertion. Build a graph whose vertices are all patches and whose edges connect conflicting patches on opposite sides. For every connected component containing patches from both sides, emit one conflict chunk. Its start is the minimum start and its end is the maximum end of its patches. Its left and right arrays are the result of applying just that side's component patches to base[start:end], preserving uncovered base lines. All other patches are applied normally. Output an array of chunks: {type:'ok', lines:[...]} for ordinary output and {type:'conflict', start, end, left:[...], right:[...]}. Traverse base from left to right, emitting conflict chunks at their component spans, and applying ordinary patches outside them. At a shared boundary, process a patch or conflict ending there before an insertion or conflict starting there. Adjacent ordinary lines, including replacement lines and untouched base lines, form one ok chunk; omit empty ok chunks. Conflict chunks are emitted even when their two alternatives are identical or empty. Empty input with no output returns [].
