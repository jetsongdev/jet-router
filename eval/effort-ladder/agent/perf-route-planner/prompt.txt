The route planning playground needs to handle a much larger synthetic transport map. The current implementation gives sensible answers on the demonstration routes but becomes impractical as the number of stops and services grows. Please retain the input and output shapes of `plan(stops, services)` and keeping the existing reporting helpers usable. The intended usage and exact boarding rules are described in the workspace documentation; treat the examples as demonstrations rather than a complete specification.

The application starts at stop zero and asks for the cheapest way to reach the last numbered stop. The planner must work for up to 200,000 stops and 200,000 services within one second in a local Node process, including its own preprocessing. The service list is a snapshot and may arrive in any order. There is no external schedule service or wall clock involved, and the test data is invented for this repository. It is fine to preprocess the entire snapshot because a caller already has all of the services when it requests a plan.

Keep the exported function synchronous and use only Node built-ins. Please do not change the public tests, which cover a few simple networks; run them with `node --test test/public.test.mjs`. The project also contains small analysis and reporting tools used by its examples. Preserve their interfaces and avoid changing callers to mask a slow or incorrect result.
