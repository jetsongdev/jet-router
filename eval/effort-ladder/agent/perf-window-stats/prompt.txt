Our telemetry playground produces a rolling distribution for a stream of synthetic measurements, but the dashboard locks up on realistic replays. Please make `windowStats(events, options)` fast enough that a replay of 200,000 events completes within one second on a local Node process. The existing small examples are useful as a smoke test, not as a performance benchmark. Keep the function synchronous and preserve its output shape so the reporting utilities continue to work.

The stream is processed in the order supplied; a result belongs to each input event, including events that do not contribute a measurement. A result contains the current watermark, the number of retained measurements, and a percentile value, or null if the window is empty. The examples in the repository use integer timestamps and numeric values. No network, external libraries, real clock, randomness, or modification of the inputs is needed. The exact window and percentile conventions are in the workspace documentation, alongside the replay rules that the dashboard and exporter share. Please use those conventions rather than changing the examples or simplifying the output.

Run `node --test test/public.test.mjs` and leave the public tests untouched. The repository contains small report and fixture helpers used by other tools; keep their interfaces working. Implement only what is needed to make this replay reliable and fast; the grading inputs are synthetic and respect the documented input constraints.
