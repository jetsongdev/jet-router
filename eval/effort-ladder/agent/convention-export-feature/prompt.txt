Our support team exports order records manually whenever a customer asks for a spreadsheet, and that process is slowing down the end-of-month review. Please add an order-history CSV export endpoint to this small service so that clients can download one page at a time. The endpoint should fit the existing request and response model and work with the in-memory data source used by the other endpoints; it should not introduce a new server framework or any external dependencies.

A client should be able to request a page for its current tenant, pass the continuation from an earlier response, and keep fetching until there is no next page. The exported data is intended to be opened in ordinary spreadsheet applications. A header is needed even when the tenant has no orders. We need the export to behave like a normal endpoint in this repository, including its established handling of access, tenant boundaries, reporting, and malformed requests. Please preserve the existing endpoints and their behavior.

There are a few implementation notes and examples in the repository from previous features. They were written by the team maintaining this service and apply to additions as well as to existing code. The supplied tests are a small smoke suite for local development; run them before you finish, and do not alter them. Keep the implementation straightforward enough that another maintainer can extend it later. Use only Node's built-in modules.
