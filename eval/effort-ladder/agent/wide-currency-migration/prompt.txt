We have been seeing reconciliation differences between the calculators and the totals screen, especially after a set of small fees is combined. Please move the service's internal money representation from floating point dollars to integer cents. The existing external JSON interface is used by other teams, so callers should continue sending and receiving the same dollar-valued JSON fields they use today. This work covers the calculators, shared helpers, summary path, and the local test support that constructs records; changing just the entry point would leave incompatible internal callers behind.

The repository has a collection of small independently deployed calculator modules rather than one central implementation. They share a record shape and should continue producing the same kind of quote, including a fee computed from the supplied rate. Some of these modules were written at different times and use different JavaScript access and import styles. Please keep those modules independently usable and preserve the existing public entry points. The data formats and accounting conventions are described in the repository; use those rather than introducing a currency package or changing consumers.

The public tests are deliberately small examples and should be left intact. Run them after the migration, preserve unrelated behavior, and use Node built-ins only. This is a local synthetic fixture: no network service is necessary. A maintainer should be able to reason about the point at which amounts enter and leave the system, and each calculator should agree with the shared helpers on the internal representation.
