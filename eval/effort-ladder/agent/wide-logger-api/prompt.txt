Our operations team is moving log ingestion to a structured pipeline, and the current free-form messages cannot be reliably grouped. Please migrate the existing task handlers to the structured logger that the service is adopting. The handlers live in separate modules because teams deploy them independently; keeping the central entry point working is necessary but will not update those deployed modules on its own.

The pipeline expects useful machine-readable fields rather than a sentence copied into a single field. An operator still needs to identify the affected item, tell accepted, failed and inspected operations apart, and see the useful parts of an error. The existing logging guide defines the event names and field conventions, and the service already has a way for tests and callers to supply a logger. Keep that injection path functional. Some handlers inspect expensive details, so the migration must not cause new work when the corresponding level is disabled.

Do not add a logging package or contact any service. Preserve the handler and service entry points, and do not change the supplied public tests. The small smoke tests exercise the service setup and ordinary success only; please run them but use the repository documentation and existing code to understand the remaining behavior. All inputs and loggers for this local task are synthetic. A consistent migration is more useful to the operations team than a compatibility wrapper that leaves most callers emitting old strings.
