We are adding another delivery partner for transactional notifications. Please add support for the Pulsar provider to the existing notification service. Product wants applications to select it by name in the same way they already select the other providers, and the service should expose the same result and failure behavior that callers receive today. A transport is injected by the caller so this task can be developed and tested without making any network requests.

The partner's wire format is described in the repository alongside the notes for the current integrations. Do not replace or disrupt the existing providers. Configuration mistakes should surface when a provider is created rather than after a message has been queued, and a failed delivery must not be mistaken for success. We also want an operator to be able to switch provider names without changing the calling code or adding a special retry loop for the new integration.

There is a small public smoke suite in the fixture. It covers everyday usage but was not intended as a complete provider certification suite. Follow the existing implementation patterns and the integration documentation, run that suite, and leave it unchanged. Keep the implementation compatible with the injected transport and clock, use Node built-ins only, and avoid any installation or network access. The request is for a working addition, not a design document.
