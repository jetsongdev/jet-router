Several customers have reported that month-end invoices sometimes differ by a few cents from the amounts they were shown during the month. A replay of the same synthetic invoice data can also sometimes produce a different breakdown. We need the invoice calculation repaired before using the replay results to investigate the reports.

Please keep the existing `createInvoice(input)` output shape and exported interface. The repository contains the billing team's calculation conventions and examples used by other reporting tools. Those conventions are part of the behavior callers rely on, including how a bill is broken down, so a change should make the complete result reproducible rather than merely forcing the final displayed amount to look plausible. The input and all examples in this exercise are newly invented. They are not real customer data, and there is no payment provider or external service involved.

Run `node --test test/public.test.mjs` after making the repair, without editing that file. The public examples are intentionally small and do not cover all of the scenarios the batch system can encounter. Keep the code synchronous, use only Node built-ins, preserve inputs, and leave unrelated helpers usable by their existing callers. We are looking for a general fix consistent with the documentation, not a hard-coded adjustment for the example amounts.
