# Claude 한 턴 effort 변경 경로 확인

상태: **적용 경로 동작 확인**. 이 기록은 enforce 구현·승인이나 추천 품질 평가가 아니다.

## 질문

플러그인이 `turn.step`에서 effort를 바꿔 넘기면 다음이 성립하는가.

1. 해당 턴의 모든 모델 요청(도구 루프 포함)에 반영되는가.
2. 서버가 바뀐 값으로 실제 처리하는가.
3. 턴이 끝나면 원래 effort로 돌아오고 사용자 설정에 남지 않는가.
4. 서브에이전트·resume·턴 도중 `/effort` 변경과는 어떻게 상호작용하는가.

## 방법

- Claude Code 2.1.283, Opus 5.5(`claude-opus-5-5`), jet-router 0.3.2(`feat/effort-router` @ `9115676`).
- 제품 코드는 바꾸지 않았다. 일회용 프로브 플러그인을 `--plugin-dir`로 추가 로드했다. 프로브는 프롬프트에 표식 `JR-LOW`가 있는 턴만 `next({ ...e, effort: 'low' })`로 넘기고, 서브에이전트 단계(`agentId`)는 건드리지 않는다. 설치된 jet-router는 off 상태로 함께 로드됐다.
- 관측 지점: transcript의 assistant 항목마다 기록되는 `effort`·`perTurnEffort`. `--debug api` 로그에는 요청 본문이 남지 않아 wire 값은 직접 확인하지 못했다.
- 서버 반영은 출력 토큰으로 비교했다. 새 headless 세션(`claude -p`)마다 한 번씩, 조건 순서를 번갈아 실행했다. 모든 조건에 같은 프롬프트(표식 포함)를 쓰고 프로브는 훅 조건에만 로드했다.
- 설정 불변은 `~/.claude/settings.json`의 SHA-1로 확인했다. `/effort` 확인 뒤에는 백업으로 복원했다.
- 모델 호출: 인터랙티브 10턴, headless 26회. Jev 호출은 없다.

## 결과

### 요청 반영과 복귀

| 턴 | 기록된 effort |
| --- | --- |
| 일반 | medium |
| `JR-LOW` + 도구 호출 1회 | low(tool_use) · low(text) |
| 일반 | medium |

해당 턴의 도구 루프 요청 전부에 반영됐고 다음 턴은 원래 값으로 돌아왔다. 실험 전후 settings 해시가 같았고 statusline effort도 바뀌지 않았다.

### 서버 동작

코드 작성 과제 1개(함수 + assert 테스트 6개), 각 3회 출력 토큰:

| 조건 | 1 | 2 | 3 | 평균 |
| --- | ---: | ---: | ---: | ---: |
| CLI `--effort xhigh` | 2,718 | 2,330 | 2,745 | 2,597 |
| xhigh에서 훅으로 low | 939 | 969 | 1,159 | 1,022 |
| CLI `--effort low` | 984 | 1,155 | 1,299 | 1,146 |

훅 조건이 CLI low와 같은 범위이고 xhigh의 약 39%다. 기록 필드만 바뀐 것이 아니라 서버가 low로 처리했다고 판단한다.

암산 과제(1~300 중 7 관련 수 세기)는 CLI low와 medium 모두 약 350토큰이라 구분력이 없어 판정에 쓰지 않았다. 같은 질문을 한 세션에서 반복한 비교도 앞 답을 반복해 무효로 처리했다.

### 경계 조건

| 조건 | 결과 |
| --- | --- |
| 서브에이전트 | 메인 턴은 low, 서브에이전트 요청 3건은 세션 값 xhigh 유지. 낮춘 effort가 서브에이전트로 번지지 않는다. |
| resume | low 턴 이후 `--resume` 일반 턴은 기본 effort. 프로브를 붙인 resume `JR-LOW` 턴은 다시 low, 이어지는 일반 턴은 기본값. |
| 턴 도중 `/effort` | `/effort`는 **실행 중인 턴의 다음 단계부터 즉시 반영**된다(`e.effort`가 바뀌어 들어옴). 항상 덮어쓰는 프로브는 이 변경을 턴 끝까지 low로 덮어썼다. 첫 단계 값과 달라지면 덮어쓰지 않는 프로브에서는 변경 직후 단계부터 xhigh로 바뀌었다. |
| `/effort`의 설정 저장 | CLI 동작대로 `modelSettings.claude-opus-5-5.effortLevel`이 저장됐다. 훅 변경과는 무관하다. |

## enforce 설계에 주는 요구사항

- 한 턴 적용은 `turn.step`의 effort 재작성만으로 가능하며 설정 파일 수정이 필요 없다.
- 턴 도중 사용자가 effort를 바꾸면(첫 단계와 다른 `e.effort`) 그 턴의 남은 단계는 덮어쓰지 않아야 한다. shadow의 `마지막 요청 …` 추적과 같은 비교를 쓴다.
- 서브에이전트는 기존처럼 대상에서 제외한다. 메인 턴 변경이 서브에이전트로 전파되지 않으므로 별도 보호 로직은 필요 없다.

## 한계

- wire 요청 본문은 보지 못했다. 근거는 transcript 기록과 출력 토큰 차이다.
- 과제 1개·3회 비교라 품질·비용 평가가 아니다. 추천 품질과 합격선은 별도 평가가 필요하다.
- 턴 도중 모델 변경, 중단 후 재시도, 다른 플러그인과의 effort 재작성 충돌은 확인하지 않았다.
