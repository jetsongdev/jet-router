# 1차 코드 리뷰와 수정

대상: `8ae3135` 이후 작업 브랜치의 턴 연결·중단·늦은 응답 경계.

## 발견·수정

1. **겹친 세 번째 제출의 오인식**: 첫 제출의 next가 끝나지 않은 상태에서 두 번째 제출이 완료되면 단일 pending 슬롯은 비워졌다. 세 번째 제출이 이를 idle 입력으로 오인해 분류할 수 있었다. 미완료 제출을 Set으로 추적하고 각 제출의 finally에서 해당 ticket만 제거한다. off/lock 상태의 입력도 원문 없이 수명만 추적한다.
2. **마지막 시간 측정 중 stale 결과 복원**: 분류 결과를 받은 뒤 지연 측정을 await하는 동안 새로운 입력이 기존 턴을 무효화해도 record를 다시 넣을 수 있었다. 시간 측정 뒤에도 valid를 확인하여 오래된 결과를 폐기한다.

두 회귀 테스트는 수정 전 각각 실패(exit 1)했고 수정 후 통과했다. 세 곳에 중복된 턴 무효화 처리를 `invalidateTurn`으로 모아 record와 prompt 참조도 함께 비우도록 소규모 정리했다. 일반 라우터 framework나 별도 상태관리 라이브러리는 도입하지 않았다.

검증: Node 26개 테스트, 설치 Claude의 mock hook 테스트 1개, manifest/module strict 검증. 실시간 대화나 실제 provider 검증은 아니다. 추가 기능과 출시 완료를 의미하지 않는다.
